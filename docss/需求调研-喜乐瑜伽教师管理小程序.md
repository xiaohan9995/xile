## 一、项目在解决什么问题

喜乐瑜伽需要一款 **微信小程序**，核心诉求可以概括为三件事：

1. **管**：教师管理委员会掌握各档教师人数、年审情况，能审核、能查询。  
2. **记**：认证教师维护自己的资质与教学相关信息，按时完成年审。  
3. **查**：学员能查到各地教师，**确认资质是否有效**；培训与活动信息后期再扩展。

一句话：**让教师资质可管理、可核验、可对外查询。**

## 二、三类用户（宏观理解）

| 角色 | 最关心什么 | 原始文档中的典型动作 |
|------|------------|----------------------|
| **教师管理委员会** | 人数、年审进度、审批、查询 | 看各档人数与年审统计；查教师；审批年审 |
| **教师** | 自己的资质有效期、年审状态 | 登录后看本人信息；提交年审申请 |
| **学员** | 教师是否「官方认证、仍在有效期」 | 按姓名/喜乐名或条件搜索；看概要信息 |

> 暂不讨论：具体登录方式、每个按钮怎么点、每张表填哪些列——**范围确认后再议。**

原始文档提到目前约有 **五档** 教师（喜乐顾问 → 喜乐瑜伽教师 → 中级 → 高级 → 智慧生命导师等），且注明 **「各档详细信息另表提供」**。

**本期只需确认：**

- 是否存在分档资料表（Excel）可后续提供？

**年审规则已在首轮沟通中初步确认**：L0-L3 两年一审，L4 三年一审，L5 无需年审；最终以 Excel 档位名称与编码映射为准。

## 四、首轮需求确认结论（已收到）

### 4.1 首期优先目标

第一期最优先上线的价值为：

1. **管委会年审管理**：教师管理委员会能查看年审情况、处理年审申请、维护教师资料。
2. **教师查询本人情况**：教师能登录后查看自己的资质、年审状态和基础信息。
3. **学员查询教师资质**：学员端首期保留教师搜索与资质有效性查看。

### 4.2 教师资料与分级

- 甲方有一份 Excel 表格详细记录所有教师情况，目前仍在做今年年审，预计下周可提供。
- 五档教师名称以该 Excel 表格中的实际描述为准，不再按前期口头名称写死。
- 首期建议采用“**后台维护基础信息，前台按权限查询展示**”的模式：管委会在 PC 后台维护教师资料；学员看到概要信息；教师看到本人信息。

### 4.3 年审规则

| 档位 | 年审周期 |
|------|----------|
| L0-L3 | 两年一审 |
| L4 | 三年一审 |
| L5 | 无需年审 |

> 档位名称与档位编码的对应关系，待 Excel 表格提供后最终确认。

### 4.4 已确认后置事项

| 模块 | 首期处理 |
|------|----------|
| 教师月度教学记录 | 后期再添加，首期不做月度填报 |
| 培训资讯 / 课程活动 | 后期再添加，首期不做内容运营后台 |
| 瑜伽工作室 | 首期增加基础展示与后台维护，不做预约/报名/支付 |
| 有赞凤凰世纪学堂 | 首期仅外链 |
| 复杂分级授权 | 后续专题再确认 |

### 4.5 组织与时间

- 日常由教师管理委员会管理和维护教师资料。
- 教师管理委员会指定专人负责每年的年审工作。
- 期望 **7 月底前完成小程序测试与上线**。

## 五、第一期建议范围（已按确认口径收敛）

### 5.1 建议纳入首期（MVP 方向）

- 管委会：**各档人数 + 年审进度概览**、教师查询、教师资料维护、年审审批  
- 教师：认证登录、本人信息、年审状态查询、年审申请  
- 学员：**教师查询 / 搜索**、查看概要信息（资质是否有效）  
- 基础账户与权限（管委会 / 教师 / 学员三类入口）

### 5.2 建议首期从简或后置

| 模块 | 建议 | 原因 |
|------|------|------|
| 教师月度教学记录 | 后期再做 | 甲方已确认月度填报可后置 |
| 培训资讯 / 课程 | 后期再添加 | 首期先不做内容运营后台 |
| 瑜伽工作室 | 首期做基础展示 | 仅展示认证工作室、地址、主理教师、开放状态 |
| 有赞凤凰世纪学堂 | 首期 **外链跳转** 即可 | 甲方已确认外链足够 |
| 消息提醒（年审到期等） | 二期 | 非原始文档硬性要求 |
| 报名 / 支付 | 二期 | 范围易膨胀 |
| 复杂「分级授权」（任意账户看某档详情） | 专题再议 | 规则复杂，可先做管委会全量权限 |

> 上表为**方向性建议**，最终以甲方快速确认表为准。
