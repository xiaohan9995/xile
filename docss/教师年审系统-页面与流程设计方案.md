# 教师年审系统 — 页面与流程设计方案（需求表版）

> 依据：`教师年审系统功能需求表.xlsx`。本方案替换旧方案中“单管理员审批、复杂授权后置”的相关设计；工作室、公告等非年审模块保持现状。

## 1. 设计目标与原则

系统服务游客核验、教师自助年审、审核小组协作和教委会发布。核心原则是：**查询公开、提交留痕、审核分工、结果发布后生效**。教师不应因登录身份选择而迷失；审核成员只能看获授权范围；任何公开结果必须有管理员发布动作。

## 2. 账号与角色

登录页只输入账号和密码，不要求预先选择身份。系统根据账号权限进入默认工作台；拥有多个角色时，在右上角“切换工作台”切换。

| 角色 | 默认工作台 | 可见数据与动作 |
|---|---|---|
| 游客 | 小程序查询 | 免登录；按地区、姓名/喜乐名或证书编号核验资质 |
| 教师 | 小程序“我的” | 本人资料、教学记录、年审申请与已发布结果 |
| 审核成员 | PC“我的审核” | 仅获分配等级/教师；提交个人审核意见 |
| 审核组长 | PC“审核小组” | 成员能力 + 查看组内意见、提交集体决议 |
| 普通管理员 | PC“年审管理” | 建批次、分配审核组、核验并发布结果 |
| 超级管理员 | PC“系统管理” | 账号、角色、授权范围、初始密码和全局配置 |

教师首次密码由超级管理员创建或重置；首次登录强制修改。教师账号以教师编号为唯一关联，不允许多人共用。

## 3. 小程序信息架构

```text
首页
├── 游客查教师
│   ├── 查询方式：地区 / 姓名或喜乐名 / 证书编号
│   ├── 地区结果列表
│   └── 教师公开详情
└── 我的（教师登录后）
    ├── 我的资料
    ├── 教学记录
    └── 年审中心
        ├── 本期年审申请
        ├── 年审进度与审核意见
        └── 历史年审记录
```

### 3.1 游客查询与教师详情

首页将“查教师”置为主操作，并先让用户选择查询方式：

1. **按地区**：省、市两级选择 → 展示教师列表；卡片显示姓名、喜乐名、等级、城市、资质状态和证书编号后四位。
2. **按姓名/喜乐名**：输入后直接给出精确或同名候选；避免同名时误入详情。
3. **按证书编号**：精确匹配，直接打开详情；未命中时提示核对编号。

公开详情按“资质核验”组织：姓名/喜乐名、等级全称、性别、所在地（省+市）、可提供教学平台、各级认证年份、当前有效期和 1–5 张照片。顶部固定展示“资质有效/即将到期/已失效”，不可向游客展示电话、审核意见或内部备注。

### 3.2 教师工作台

“我的”首页使用三张任务卡：**资料待完善、教学记录、当期年审**。资料页分为“公开展示资料”和“联系/内部资料”；编辑后显示“待管理员确认”，保留当前已发布版本。照片最多五张，可排序、删除和预览。

教学记录是独立于年审材料的连续记录：日期、地区/平台、课程或活动名称、时长、参与人数、说明、佐证附件。支持草稿、提交和按月份筛选；本期年审可自动引用已提交记录，教师仍可手动增补材料。

年审中心顶部显示本期状态、截止日和下一步：

```text
待提交 → 已提交 → 审核中 → 待发布 → 已发布（通过 / 未通过）
```

“已发布”后才显示审核小组结论、各成员公开意见、核定级别及新的有效期；审核中仅显示进度，不提前泄露未定稿意见。未通过状态必须显示后续操作，例如“补充材料后重新提交”。

## 4. PC 管理后台信息架构

```text
工作台
├── 本期年审总览
├── 年审批次与应审名单
├── 审核分配
├── 我的审核 / 审核小组（按角色显示）
├── 发布中心
├── 教师档案
├── 教学记录
└── 系统管理（超级管理员）
    ├── 账号与角色
    ├── 审核小组与授权范围
    └── 教师资料导入
```

### 4.1 本期年审总览

进入后台默认看到当前批次：应审人数、未提交、已提交、审核中、待发布、已通过、未通过。每个数字均可点击进入对应名单。顶部提供“创建/切换年审批次”，并明确本期规则、开始日、提交截止日和发布日，避免用自然年份替代业务批次。

### 4.2 审核分配

管理员先创建审核小组（组长、成员），再按等级或指定教师分配。分配页以“教师—当前等级—所属审核组—进度”列表呈现，禁止同一教师在同一批次被多个组并行处理，除非管理员显式转组并留下原因。

### 4.3 审核工作台

审核成员列表只显示获授权教师，并按“待我处理/已提交/组长已提交决议”筛选。详情页固定三栏：

- 左栏：教师公开档案、本期教学记录、年审材料；
- 中栏：个人审核意见表（建议级别、结论、意见、附件）；
- 右栏：进度轨迹与同组意见。成员只能查看已提交意见，不可修改他人内容。

组长在全部必填成员意见提交后填写“审核小组集体决议”。提交后锁定组内意见，状态转为“待发布”。

### 4.4 发布中心

普通管理员在发布前核对教师、成员意见、组长决议、核定等级和新的有效期。操作为“退回审核组”或“正式发布”；正式发布必须二次确认并写入发布人、发布时间、发布版本。仅正式发布会更新教师当前等级/有效期并向教师端展示结果。

## 5. 必要数据与状态设计

现有单条 `annual_reviews` 不能承载协作审核，应扩展为以下业务对象：

| 对象 | 关键字段 |
|---|---|
| 年审批次 | 名称、规则、开始/截止/发布日、状态 |
| 应审名单 | 批次、教师、应审原因、当前状态、审核组 |
| 审核小组与授权 | 组长、成员、等级范围、教师范围、生效期 |
| 成员意见 | 审核人、建议等级、结论、意见、提交时间、附件 |
| 小组决议 | 组长、集体结论、核定建议、提交时间 |
| 发布结果 | 发布人、发布版本、最终等级、有效期、发布时间 |
| 教学记录 | 教师、日期、平台、内容、时长、佐证、状态 |

档位先按最新表展示 L0–L4。当前系统保留的 L5 及原有 2/3 年周期不得直接沿用；上线前需由业务确认是否仍保留 L5，以及每档应审规则如何生成。

## 6. 实施顺序与验收重点

1. **第一阶段**：批次、角色/授权、审核组、成员意见、组长决议、管理员发布和总览统计。
2. **第二阶段**：教师账号密码、完整教师档案、照片相册、教学记录和资料修改审核。
3. **第三阶段**：游客三种查询模式、导入模板升级、通知与导出。

验收时至少覆盖：同一人多角色切换、越权无法读取非授权教师、未发布结果对教师不可见、发布后档案与有效期同步、地区/姓名/编号三种查询均可得到正确结果，以及全流程操作日志可追溯。
