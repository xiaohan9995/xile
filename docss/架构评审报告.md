# 架构评审报告

> **评审时间**：2026年6月22日  
> **评审角色**：架构师  
> **项目**：喜乐瑜伽教师认证中心 MVP  
> **评审范围**：后端架构、前端架构、部署架构

---

## 1. 评审结论

当前架构基本满足 MVP 交付要求，整体清晰、技术选型合理。经评审发现 **7 项结构性问题**，已按两阶段完成优化。

---

## 2. 发现的问题与优化

### 阶段一（基础加固，已完成）

| 编号 | 问题 | 风险等级 | 优化措施 |
|------|------|----------|----------|
| A-01 | Config 类无校验，生产环境可能使用 dev 密钥 | HIGH | 新增 `ProductionConfig`，启动时校验 SECRET_KEY、JWT_SECRET_KEY、MYSQL_DATABASE_URI，缺失即抛 RuntimeError |
| A-02 | 无全局 JSON 错误处理，框架返回 HTML 错误页 | MEDIUM | 注册 400/404/405/413/429/500 全局 errorhandler，统一返回 `{"error": "..."}` |
| A-03 | Health check 不探测 DB | MEDIUM | `/api/health` 增加 `SELECT 1` 检测，DB 不可达返回 503 |
| A-04 | 关键端点无速率限制 | HIGH | 引入 flask-limiter，login 10/min、bind-phone 5/min、search 60/min、upload 10/min |

### 阶段二（结构优化，已完成）

| 编号 | 问题 | 风险等级 | 优化措施 |
|------|------|----------|----------|
| A-05 | 两个 Blueprint 各 800+ 行，职责混杂 | MEDIUM | 拆分为 14 个子模块（mp: auth/teachers/studios/reviews/uploads/helpers；admin: auth/teachers/studios/reviews/system/helpers） |
| A-06 | 业务逻辑嵌入路由处理函数，无法复用且难测 | MEDIUM | 抽取 Service 层（review_service、teacher_service、auth_service），路由函数仅做参数解析 + 调用服务 + 序列化响应 |
| A-07 | 无结构化日志，无请求追踪 | LOW | 引入 python-json-logger + request-id 中间件，自动生成或透传 X-Request-Id |

## 3. 优化后架构

```
backend/app/
├── __init__.py          # App factory + error handlers + health check
├── config.py            # Dev/Prod/Test config with production validation
├── extensions.py        # db, jwt, migrate, limiter
├── logging.py           # JSON logger + request-id middleware
├── models/              # SQLAlchemy models
├── services/            # Business logic layer
│   ├── auth_service.py
│   ├── review_service.py
│   └── teacher_service.py
├── api/
│   ├── mp/              # Mini program API (6 modules)
│   └── admin/           # Admin API (6 modules)
├── utils/
└── seed.py
```

### 分层职责

| 层 | 职责 | 示例 |
|----|------|------|
| Route (api/) | HTTP 协议处理：解析参数、权限装饰器、序列化响应、限流 | `@mp_bp.post("/reviews")` |
| Service (services/) | 业务逻辑：校验规则、状态机、计算、事务管理 | `submit_review(user_id, teacher_id, year, files)` |
| Model (models/) | 数据映射：字段定义、关系、查询 | `Teacher`, `AnnualReview` |

## 5. 部署架构评审

当前方案：单 Docker 容器 (Nginx → Gunicorn → Flask)，部署在微信云托管。

**优点**：
- 零运维复杂度，适合 MVP 阶段
- 无需 ICP 备案（wx.cloud.callContainer）
- 单容器内通信零延迟

**风险与建议**：
- Nginx 和应用同容器，更新需整体重启 → MVP 可接受，后续可拆分
- SQLite dev / MySQL prod 差异 → 已通过 Config 类隔离，测试环境使用 SQLite 够用
- 无水平扩展能力 → 微信云托管支持自动扩缩容（实例级），当前足够
