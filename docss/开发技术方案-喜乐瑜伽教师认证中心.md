# 喜乐瑜伽教师认证中心 — 开发技术方案

> **版本**：V1.1  
> **日期**：2026年6月19日  
> **状态**：开发进行中  
> **依据**：《产品设计方案-喜乐瑜伽教师认证中心.md》《技术选型报告-喜乐瑜伽教师管理小程序.md》  
> **首期范围**：教师认证查询、教师本人认证与年审、管委会年审管理、教师资料维护、瑜伽工作室基础展示与维护。

---

## 1. 技术结论

首期采用 **小程序 + PC 管理后台 + Flask 后端 + TDSQL-C MySQL + 微信云托管单容器** 的方案。

| 层 | 技术方案 | 结论 |
|----|----------|------|
| 小程序 | 微信原生小程序 + Wot UI | 首期不做跨端，原生小程序最稳 |
| PC 管理后台 | Vue 3 + Vite + Element Plus | 管委会表格、审批、导入更适合 PC |
| 后端 | Python 3.10+ + Flask + SQLAlchemy | 业务以 CRUD、年审状态机、导入为主，Flask 足够 |
| 数据库 | TDSQL-C Serverless MySQL | 教师、年审、工作室是关系型数据 |
| 文件存储 | COS 或云托管对象存储 | 年审材料、证书图、工作室图片 |
| 部署 | 微信云托管单容器，Nginx + Gunicorn | `/admin` 静态后台，`/api` 后端接口 |
| 鉴权 | 小程序 OpenID + 管理端 JWT | 双端隔离，后端统一裁剪字段 |

不采用 uni-app/Taro、纯云函数、Spring Boot、自建 ECS。原因是首期没有跨端诉求，业务需要统一 API 和关系型数据，团队迭代效率优先。

## 2. 总体架构

```text
微信小程序
  ├─ 学员：教师查询、工作室查看
  └─ 教师：本人认证、年审申请、年审记录
       │ wx.cloud.callContainer
       ▼
微信云托管单容器
  ├─ Nginx :80
  │   ├─ /admin  → Vue 管理后台静态资源
  │   └─ /api    → Flask / Gunicorn
  └─ Flask API
      ├─ /api/mp/*
      └─ /api/admin/*
       │
       ├─ TDSQL-C MySQL
       └─ COS / 对象存储

PC 管理后台
  └─ https://xxx.run.tcloudbase.com/admin
       │ HTTPS /api/admin/*
       ▼
    Flask API
```

核心原则：

- 小程序只提供查询、自服务和申请，不提供管委会管理入口。
- 管委会所有写操作只走 `/api/admin/*`。
- 后台维护基础数据，前台按角色展示裁剪后的字段。
- 年审周期配置进数据库，不写死在前端。

## 6. 年审规则

| 档位 | 周期 |
|------|------|
| L0-L3 | 两年一审 |
| L4 | 三年一审 |
| L5 | 免审 |

实现方式：

- 周期配置保存在 `teacher_tiers.review_cycle_years`。
- L5 设置 `review_required = false`。
- 年审通过时，由后端根据档位周期计算 `next_valid_until`。
- 特殊教师如需覆盖周期，二期可在 `teachers` 增加 override 字段，首期不做。

## 8. 权限与安全

### 8.1 小程序

- 所有页面强制登录：`onLoad` 调用 `auth.requireAuth(pagePath)`，未登录跳转 `packageTeacher/login/login`。
- 登录流程：App `onLaunch` 静默调 `wx.login` → 后端换 OpenID → 签发 JWT；登录页通过 `getPhoneNumber` 绑定手机号。
- 教师身份通过 `User.teacher_id` 关联，由管委会在后台"权限管理"中设置。
- `GET /teachers/me/certification` 仅教师角色可调用（JWT + `user.teacher_id` 存在）。
- `POST /reviews` 强制所有权校验：`user.teacher_id == teacherId`，不可代他人提交。
- `GET /teachers/:id/certification` 公开访问仅返回概要 DTO，本人登录时返回完整数据。

### 8.2 管理端

- 管理员账号登录后获取 Bearer Token（dev 模式为静态 token `dev-admin-token`）。
- 所有 `/api/admin/*` 接口通过 `require_admin_token` 装饰器保护。
- 首期角色分 `admin` / `super_admin`，后台"权限管理"页面可邀请新管理员。
- 管理员可查看/修改教师全字段，包括 `committeeRemark`（管委会备注，学员和教师不可见）。
- 管理员可设置小程序用户角色（`PUT /users/:id/role`），将学员升级为教师并关联 `teacher_id`。

### 8.3 字段裁剪（已实现）

| DTO | 使用场景 | 字段原则 | 对应接口 |
|-----|----------|----------|----------|
| `TeacherSummaryDTO` | 学员/教师查他人 | 无手机号、无备注、无 daysLeft、无 reviews | `GET /teachers/search`、`GET /teachers/:id/summary`、`GET /teachers/:id/certification`（非本人） |
| `TeacherSelfDTO` | 教师本人 | 含 daysLeft、reviews、phone、reviewCycleYears | `GET /teachers/me/certification`、`GET /teachers/:id/certification`（本人） |
| `TeacherAdminDTO` | 管委会后台 | 全字段、committeeRemark、phone | `GET /admin/teachers`、`GET /admin/teachers/:id` |
| `StudioPublicDTO` | 小程序工作室 | 仅展示 status=open | `GET /studios`、`GET /studios/:id` |
| `StudioAdminDTO` | 管理后台 | 全字段、含 hidden 状态 | `GET /admin/studios` |

## 10. 文件与上传

首期文件类型：

- 年审材料：PDF、图片。
- 教师证书：图片或 PDF。
- 工作室图片：图片。

建议策略：

- 文件先上传到私有对象存储。
- 数据库只保存文件 key、名称、类型、大小。
- 下载时由后端校验权限后返回临时访问链接。
- 小程序公开展示图可使用公开读或后端签名 URL，按实际云资源决定。

## 11. Excel 导入

导入流程：

1. 管理端上传 Excel。
2. 后端解析并生成预检结果。
3. 预检检查：必填字段、教师编号重复、档位是否合法、日期是否合法、手机号格式。
4. 前端展示错误行。
5. 管委会确认后写入 `teachers`、`teacher_details`。
6. 写入 `import_batches` 和 `audit_logs`。

首期不做自动合并复杂历史冲突。重复教师编号默认更新已有记录，具体策略需在拿到 Excel 后最终确认。

## 14. 开发顺序

### 阶段 1：工程骨架 ✅

- 建 `backend`、`admin-src`、`miniprogram`。
- 配置 Docker、Nginx、Gunicorn。
- 打通 `/api/health`。

### 阶段 2：数据模型与后台基础 ✅

- 建表和 seed 数据。
- 管理员登录。
- 教师列表、教师详情、档位配置。

### 阶段 3：小程序查询 ✅

- 首页。
- 教师查询与详情。
- 工作室列表与详情。

### 阶段 4：年审主流程 ✅

- 登录注册（微信静默登录 + 手机号绑定）。
- 我的认证。
- 年审申请与年审记录。
- 证书查看。
- 管理端年审审批。

### 阶段 5：权限隔离与角色管理 ✅

- 全局登录守卫（所有页面必须登录）。
- DTO 字段裁剪（公开概要 vs 本人完整 vs 管理端全字段）。
- 所有权校验（年审提交、认证数据访问）。
- 管理端用户角色设置（学员↔教师绑定）。

### 阶段 6：导入与收尾 ✅

- Excel 预检与导入。
- 看板统计与数据分析。
- 系统设置。
- 权限管理。

### 阶段 7：部署联调（进行中）

- Docker 构建与云托管部署。
- TDSQL-C MySQL 连接配置。
- COS 文件存储对接。
- 微信审核与发布。
